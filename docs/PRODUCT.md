# 雅思 AI 自学系统：产品设计文档

> **状态：开发中。** 代码在 `m1-kg-rag` 分支，四个模块的 MVP 已跑通（2026-11-23），正在进入精调阶段。
> 本文讲"为谁做、做什么、为什么这样做"；实现细节见 [README](../README.md) 和技术设计文档。
> 最后更新：2026-11-27

## 1. 背景与问题

雅思四科里，听力和阅读有标准答案，考生刷真题就能自查；写作和口语没有标准答案，自学时最难解决的是：

1. **不知道自己几分**：写完作文、录完口语，没人判分，不知道离目标分还差多远、差在哪一项。
2. **反馈不可执行**：网上的范文和"高分句型"是通用的，说不清"我这篇"该怎么改。
3. **人工批改贵且慢**：一篇作文批改几十元到上百元，要等几天，练得越多越贵，所以考生练得少。
4. **错题解析分散**：真题书、解析书、音频是分开的，对完答案还要翻书找解析。
5. **不知道下一步练什么**：练习凭感觉，不会针对薄弱项安排。

## 2. 目标用户

| 用户 | 描述 | 核心需求 |
| --- | --- | --- |
| **主要：自学考生** | 以中文为母语，目标 6.5–7.5，备考 1–3 个月，没有报班或报班后需要额外练习 | 随时练、马上知道分数和改法、少花钱 |
| 次要：老师 / 助教 | 带多个学生，批改量大 | 先由系统初评、标出错误，人工只复核有分歧的部分 |

MVP 只服务主要用户；老师端（批量批改、复核队列）放在后续版本。

**典型场景**：备考第 4 周的考生，阅读稳定在 7 分，写作卡在 6 分。晚上写一篇 Task 2，想知道这篇几分、哪一项拖后腿、哪几句该怎么改，第二天再练一篇针对弱项的题。

## 3. 产品目标与非目标

**目标**
- 一个地方完成听说读写四科练习。
- 客观题即时判分，并给出对应的中文解析。
- 写作、口语给出分项分数、错误标注和**引用依据**的改进建议，几十秒内返回。
- 根据每次练习更新掌握度，推荐下一题。

**非目标（当前不做）**
- 替代真人考官：分数是练习参考，不承诺与考试一致。
- 课程、视频、词汇背诵等内容型功能。
- 托福等其他考试：数据层已按考试划分，接口已预留，暂不实现。
- 多用户账号、付费、移动端。

## 4. 核心流程

### 4.1 写作
1. 系统根据薄弱维度和题型选题：优先用真题，没有合适的就生成新题。生成题会检查与真题的相似度，过高就重写。也可以输入自己的题目。
2. 考生写作，页面显示计时和字数。
3. 提交后约 20–40 秒，返回四项分和总分、标注在原文上的错误、3–6 条改进建议（每条都附依据，并改写一句考生自己的原句），以及升到下一档需要做到什么。
4. 系统更新档案，下一次练习会针对最弱的一项选题。

### 4.2 听力 / 阅读
1. 从 88 套真题（剑4–13、17 学术类，听力、阅读各 44 套）中选一套。
2. 页面显示书页原图（保留表格、地图、流程图），听力可播放分段音频。
3. 在 40 个答题框里作答后交卷：返回原始分、估算分数段、逐题对错，错题附中文解析。

### 4.3 口语
1. 选 Part 1/2/3，系统给出一道真题；Part 2 有 1 分钟准备倒计时。
2. 浏览器录音，录音在本机转写，不上传外部服务。
3. 返回四项分、转写稿、语速和停顿等流利度数据，以及改进建议。结果统一标注"仅供参考，建议人工复核"。

## 6. 关键产品决策

| 决策 | 原因 |
| --- | --- |
| **先做雅思，托福延后** | 先把一个考试做深；数据层按考试划分，以后加托福只需换考试包（题型、评分标准、题库）。 |
| **先跑通四个模块的 MVP，再精调** | 尽早验证完整体验和架构；精调的优先级要看真实使用中哪块最影响体验。 |
| **反馈必须引用证据，否则丢弃** | 考生最怕"AI 一本正经地胡说"。每条建议必须对应官方评分描述、考官评语或范文；错误片段必须真的出现在原文里。宁可少给，也不给错的。 |
| **写作评分：模型和 LLM 各占 50%** | 训练数据的分数被发现是批量生成的，按它拟合出的权重几乎不给 LLM 分量。改用 12 篇真考官评分的作文验证：LLM 有 9 篇与考官相差在 0.5 分以内。所以不按拟合结果，而是两者各一半；拟合权重保留，供以后有可信数据时参考。 |
| **分歧大时自动复查，仍不一致就标记人工复核** | 模型与 LLM 相差超过 1 档，说明至少有一方没把握。先让分析环节针对分歧维度重新看一遍；仍不一致就如实告诉用户"这项不确定"，而不是给一个看似精确的数。 |
| **口语一律标"仅供参考"** | 没有口语评分训练数据，转写会修正口误，发音还不能评。如实说明，避免误导备考判断。 |
| **录音在本机转写** | 语音属于个人敏感数据；本地 Whisper 足够用，同时省掉转写费用。 |
| **听力 / 阅读显示书页原图，而不是重新排版** | 题目里的表格、地图、流程图重排成本高且容易出错；原图最接近考试体验。 |
| **版权材料只放本地** | 剑桥真题、音频、提取出的答案和解析不进代码仓库，由用户导入自己持有的资料。 |
| **控制 LLM 成本** | 写作每次约 3–4 次调用、口语约 3 次；批量评估或打标签前先确认预算。 |

## 7. 成功指标

| 类别 | 指标 | 当前 | 目标 |
| --- | --- | --- | --- |
| 评分准确度 | 写作与真考官分数相差 ≤ 0.5 分的比例 | LLM 9/12（样本太少） | ≥ 80%，验证集 ≥ 50 篇 |
| | 写作模型 QWK（可信标签上） | 0.43（标签不可信） | ≥ 0.6 |
| | 口语与真考官相差 ≤ 0.5 分的比例 | 未测 | 先建标注集 |
| 反馈质量 | 建议被引用证据支撑的比例 | 100%（无依据的会被丢弃） | 保持 |
| | 人工抽检"建议可执行"比例 | 未测 | ≥ 80% |
| 内容覆盖 | 答案提取覆盖率 | 约 97.5% | ≥ 99%（可人工补录） |
| | 错题能找到中文解析的比例 | 听力 59%、阅读 68% | ≥ 85% |
| 检索 | hit@1 / MRR | 0.82 / 0.88 | 扩充评测集后 ≥ 0.85 |
| 体验 | 写作提交到出结果的耗时 | 约 20–40 秒 | ≤ 30 秒 |
| 使用 | 每周人均练习次数、7 日留存 | 未上线 | 小范围试用后设定 |

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 分数不准，误导备考判断 | 显示分数区间和来源（模型 / LLM），分歧大时标"待复核"；口语统一标注"仅供参考"。 |
| LLM 编造错误或建议 | 错误片段必须能在原文中找到；建议必须引用证据；每次过程完整记录，可回放检查。 |
| 版权 | 不分发真题，只处理用户自己导入的资料。 |
| LLM 成本随使用量上升 | 能用规则和本地模型的就不调 LLM；有离线模式；单次调用次数固定可控。 |
| 训练数据质量 | 不盲信公开数据集：用真考官样本校验，必要时自建标注集。 |
